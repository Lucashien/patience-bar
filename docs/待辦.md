## 新功能（已記下，尚未開工）

- [ ] **大幅下降時通知對方**：血條一次或短時間內掉太多，推播給對方。要討論：門檻怎麼定、是否合併連續下降、通知文案維持第一人稱說需求、是否需要對方的通知權限與 push（和「小工具即時更新」共用推播基礎）。
- [ ] **可選填的原因**：使用者按「我有點煩」或「我好了」時，可以寫下降／上升原因；預設不填，不能變成阻擋操作的步驟。要討論：輸入介面放哪（按完後的輕量提示？）、字數上限、對方是否看得到、事件資料要加欄位。

- [ ] **幫對方充電**（產品原文的點子，使用者覺得好，之後實作）：對方看到我快沒耐心，可選說好話／請喝飲料／抱抱，我的耐心回升，我看得到對方做了什麼。引擎與文案已有舊版程式（`PatienceEngine.charge`、`Copy.chargeTitle`），但畫面無入口、未驗證。要討論：是否仍有每日上限、文案維持第一人稱、是否需要推播通知我被充電。這是「對方可為」的第一個具體候選，開工前先與使用者確認範圍。
- [ ] **拿掉每天換日重設滿格**（使用者已決定）：`PatienceEngine.current`／`settled` 的跨日分支、`dayKey` 相關欄位與測試 `testNewDayResetsToFull`。順便可簡化小工具的 5 分鐘時間軸（值不再隨時間變）。
- [ ] **沒配對就進不了首頁**：本機模擬模式也要先取暱稱才能進（`PairingView` 的本機按鈕目前可空名）。使用者說之後補。
- [x] （規則已改且 emulator 測試 37 項通過，2026-11-01；**尚未發布到 Firebase Console**）**Firestore 規則強制「只能改自己的條」**（核心機制）：`users/{uid}` 更新目前允許任一成員改對方的 `base` 等欄位，要收成只有本人能寫。要連動：`FirestoreBackend` 的 poke／charge、`Tests/FirestoreRules` 的規則測試、新版規則手動發布。未來做「充電」時，要設計成不需要寫對方的條（例如充電寫成事件，由本人端套用）。
