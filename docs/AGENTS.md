# 文件協作規則

## 原則

- 文件用繁體中文；程式碼、識別碼、指令保留原文。重點先行、短句、每點一件事。
- 程式碼是唯一主檔。文件只寫「是什麼、為什麼、驗證到哪」，**不複製程式碼**；需要時指向檔案路徑。
- 連結用一般 Markdown 相對連結。

## 功能狀態要分清楚

每項功能分開標：

- **實作**：程式裡有。
- **驗證**：實際跑過，寫日期與環境（實機／模擬器／單元測試／電腦呼叫 API）。
- **未驗證**：寫了但沒測。

編譯成功不等於功能可用。被移除的功能保留紀錄，寫明誰決定、何時、為什麼。

## 安全

- **不寫入**：`GoogleService-Info.plist` 內容、API key、邀請碼實例、帳號密碼。
- 只寫格式與規則，不寫實例。
- 私人連結（例如設計稿）要註明「僅本人可開」。

## 改動後怎麼更新

1. 改了功能或實測了 → 更新 [功能與驗證狀態](功能與驗證狀態.md) 並改日期。
2. 做了取捨或使用者改變決定 → 在 [設計決策](設計決策.md) 加一列。
3. 發現問題或有新想法 → 寫進 [待辦](待辦.md)。
4. 踩到坑 → 寫進 [開發備忘](開發備忘.md)。
5. 在 [log](log.md) 最上面加一行。
6. 對照 `git log` 寫 commit 或分支；未 commit 的改動明說。
